## Известное условие краха (не переоткрывать)

Буфер назначения в цели — **константа 2500 байт**. Копирование идёт от позиции сразу
за маркером `/start`, длина берётся из шапки конфига. Переполнение получается, если:

1. данные вставлены **сразу за маркером** (допись в конец файла не влияет!);
2. данных больше, чем 2500 байт;
3. в шапке завышено поле длины (в проверке — смещение 8, `0xFFFFFFFF`).

Минимальный рецепт: `config_2[54:54] = b"b" * 5120` и `config_2[8:12] = FFFFFFFF`.

## Этап 1 — фаззер (`lab1/fuzzer.py`, один файл)

Только stdlib: `argparse`, `random`, `struct`, `subprocess`, `pathlib`, `ctypes`
(для регистров), `json`.

Мутации (все из ТЗ):

| Функция | Что делает |
|---|---|
| `mut_byte` | замена одного байта |
| `mut_multi` | замена нескольких байт |
| `mut_boundary` | граничные значения: `00, FF, FFFF, FFFFFF, FFFFFFFF`, половины ±1 |
| `mut_append` | допись в конец |
| `mut_expand` | вставка внутрь (файл длиннее) |
| `mut_delim` | порча/удлинение вокруг `,:=;` |

Запуск: писать мутант в `work/config_2`, запускать `work/vuln2.exe` с `cwd=work`.
Краш = код возврата `0xC000xxxx` (`exit(-1)` при неверном варианте крашем не считать).
При крахе: сохранить `crashes/crash_<N>.bin` и дописать строку в `crashes/log.txt`
(номер прогона, смещение, было → стало).

Режимы:

- `auto --seq`: по каждому смещению перебрать граничные значения (на месте).
  **Дополнительно (это ключ):** вторая фаза — то же, но на файле с вставкой
  `b"b" * 5120` за маркером; этого достаточно, чтобы краш нашёлся сразу.
- `auto --cov`: `drrun -t drcov`, считать базовые блоки, хранить входы, давшие новые
  BB, выбирать из них родителя. Журнал `adapt.log`: номер прогона, `from → to`,
  причина (`gain` / `shrink` / `plateau`), BB. Это доп. задание.
- `run`: один запуск текущего `work/config_2` + регистры, если упало.

## Этап 2 — IDA

1. Вернуть `lab1/ida/find_calls.py` из git.
2. Запустить (база уже есть, поэтому быстро):

```powershell
& 'C:\Tools\IDAPro77\idat64.exe' -A -L"<лог>" -S"<абсолютный путь>\lab1\ida\find_calls.py" `
  "<абсолютный путь>\lab1\work\vuln2.exe"
```

Важно: пути **абсолютные**; IDA виснет на автоанализе — запускать в фоне или с
таймаутом, результат забирать по файлу `calls.txt`.

3. В отчёт: скриншот консоли IDA + участок дизасма и псевдокод на C.

## Этап 3 — x32dbg (скриншоты)

Открыть `lab1/work/vuln2.exe`, положить в `work` краш-конфиг, снять:
адрес приёмного буфера, адрес сохранённого адреса возврата (`EBP+4`), момент падения.
