## Этап 2 — фаззер

Файлы (stdlib: `argparse`, `ctypes`, `pathlib`, `struct`, `subprocess`, `hashlib`):

| Файл | Роль |
|---|---|
| `fuzzer.py` | меню и CLI |
| `mutations.py` | мутации из ТЗ |
| `runner.py` | запуск с/без `drrun`, таймаут, без окна WER (`SetErrorMode`) |
| `coverage.py` | разбор `drcov`, множество BB по двум модулям |
| `debugger.py` | `DEBUG_ONLY_THIS_PROCESS`, Wow64-CONTEXT, дамп стека по ESP |

Меню:

1. Авто: последовательная замена байт (граничные значения)
2. Авто: coverage-guided очередь
3. Замена 1 / нескольких байт
4. Допись в файл
5. Расширение / удлинение
6. Поиск разделителей `,:=;`
7. Один запуск + регистры, если упало

CLI те же режимы: `python fuzzer.py auto --seq`, `python fuzzer.py auto --cov`, …

**Последовательный авторежим:** каждое смещение × `0x00`, `0xFF`, `0xFFFF`, `0xFFFFFF`, `0xFFFFFFFF`, половины и ±1 из ТЗ. Стоп: краш или конец прохода.

**Coverage-режим:** первый сид — оригинальный `config_2`. Слепые мутации (байт, несколько, допись, границы, удлинение). Запуск: `bin32\drrun.exe -t drcov -- vuln2.exe`. Новый BB в `vuln2.exe` или `func.dll` → сид в очередь. Стоп: краш, N поколений без новых BB, или `--max-runs`.

**Краш:** файл + текстовый лог (код, EAX…EIP, ESP/EBP, стек) в `lab1/crashes/`. Это артефакт отчёта и задел на lab2.

В код фаззера **не** зашивать `/start`, `shell_len`, смещения 4/8. Если слепой прогон за разумное время не крашит — остановиться и спросить, не включать «smart» самовольно.

Готово, когда: меню и CLI работают; оба авторежима гоняются; покрытие читается; на искусственном/найденном краше в логе есть код + регистры + стек; оригинал `vulns/config_2` бит-в-бит тот же.

## Этап 3 — IDAPython

`lab1/ida/find_calls.py`. Запуск: `ida.exe`, File → Script file.

Искать импорты ввода (`fread`, `fscanf`, `read`, `fgets`, `fopen`, …) и небезопасные (`strcpy`, `sprintf`, `strncpy`, `memcpy`, `memmove`, …). На каждую — имя и адреса всех `call`. Вывод: консоль IDA и `lab1/ida/calls.txt`.

Не фильтровать по подстроке `mem`/`str` в имени (чужой IDC так ловит `GetLastError` / `strlen`).

Готово, когда скрипт на `vuln2.exe` печатает как минимум `fread` и `memcpy` с адресами вызовов.

## Этап 4 — прогон

Пользователь гоняет `auto --seq` и `auto --cov`. Агент смотрит логи. Краш не затирать.

Если краша нет: сначала диагностика (`drrun` жив, множество BB растёт, WER не блокирует). Smart-мутатор только после явного согласия.

Готово, когда в `lab1/crashes/` лежит конфиг, роняющий `vuln2.exe`, плюс лог регистров.

## Этап 5 — разбор

Пользователь в GUI, агент подсказывает адреса.

1. IDA: скрипт → `fread`/`memcpy` → псевдокод участка на C.
2. x32dbg: `work\vuln2.exe` с краш-`config_2`. Снять: размер буфера, адрес начала буфера, адрес saved EIP, регистры в падении (сверить с логом фаззера).
3. В отчёт: тип (нет проверки длины → stack overflow), ограничения эксплуатации, фикс (`shell_len <= dst_len` до `memcpy`).

`vuln*.exe` не патчить.

Готово, когда есть скрины/числа: буфер, saved EIP, дизасм с комментариями, псевдокод C.
