# Фаззер lab1 (вариант 2)

Слепой мутационный фаззер файла `config_2` для `vuln2.exe`. Формат конфига в код не
зашит: ни `/start`, ни имена полей, ни их смещения. Покрытие снимает DynamoRIO `drcov`.
Доп. задание: планировщик сам меняет стратегию мутаций по результатам покрытия.

Python 3.12, только стандартная библиотека.

## Запуск

Из этой папки (`lab1/fuzzer/`):

```text
py -3.12 fuzzer.py                      меню
py -3.12 fuzzer.py auto --seq           детерминированные проходы (граничные + удлинение)
py -3.12 fuzzer.py auto --seq --passes H        только проход H (находит краш)
py -3.12 fuzzer.py auto --seq --passes A        только проход A
py -3.12 fuzzer.py auto --seq --max-runs 5000   ограничить число прогонов
py -3.12 fuzzer.py auto --cov           покрытие drcov + адаптация стратегий
py -3.12 fuzzer.py auto --cov --deep    остановиться, когда все стратегии испробованы
py -3.12 fuzzer.py auto --cov --max-runs 800
py -3.12 fuzzer.py mutate combo         одна мутация выбранного типа и запуск
py -3.12 fuzzer.py run                  один запуск текущего lab1/work/config_2
```

Меню без аргументов:

| Пункт | Что делает |
|---|---|
| 1 | то же, что `auto --seq` (проходы A+B+C+D) |
| 2 | то же, что `auto --cov` |
| 3 / 3a | замена 1 байта / нескольких |
| 4 / 5 | допись в конец / вставка внутрь (удлинение) |
| 6 | мутация вокруг разделителей `,:=;` |
| 7 | запуск `work/config_2`; при падении — регистры и стек |
| 0 | выход |

Остановить авторежим: Ctrl+C. Краш не затирается.

## Проходы режима `auto --seq`

| Проход | Содержание | Прогонов на файле 1123 байта |
|---|---|---|
| A | каждое смещение × граничные значения ТЗ (`00, FF, FFFF, FFFFFF, FFFFFFFF`, половины ±1) | 15 722 |
| B | удлинение файла блоками по 1 КБ | 6 |
| C | граничные значения в 4-байтных полях на удлинённом файле | 11 200 |
| D | обрезка файла | 4 |
| E | длинный файл (допись) × большие значения в 4-байтных полях | 4 200 |
| F | длинный файл × два испорченных поля за прогон | 3 348 |
| G | файл вдвое больше буфера × поле = `0xFFFFFFFF` | 560 |
| H | **вставка данных сразу за маркером** × два поля = `0xFFFFFFFF` | 1 116 |

Проход H — найденное условие переполнения (см. `lab1/report/lab1_report.md`, раздел 7):
данные обязаны лежать сразу за маркером (допись в конец в копирование не попадает),
а два поля длины в шапке должны быть завышены. Проход H находит краш на первом прогоне.

## Режим `auto --cov`

1. Калибровка оригинала под `drrun -t drcov` — начальное множество базовых блоков (BB).
2. Мутант с новыми BB сохраняется в `corpus/` и попадает в очередь сидов.
3. Родитель выбирается из трёх источников: сиды с новым покрытием, самый длинный вход,
   исходный конфиг.
4. Стратегию выбирает `adapt.py` (см. ниже).
5. Стоп: краш, `--max-runs`, Ctrl+C или `--deep` при исчерпании стратегий.

## Автоматический режим адаптации (доп. задание)

Сигналы по результатам покрытия:

| Сигнал | Условие | Реакция |
|---|---|---|
| `gain` | появились BB, которых не было в глобальном множестве | вес стратегии ×2 (потолок 16), сид в очередь |
| `shrink` | `BB_run < BB_parent` и новых BB нет («покрытие уменьшилось») | вес ×0.5 (пол 0.25); после 3 shrink подряд — смена стратегии |
| `plateau` | новых BB нет, покрытие не уменьшилось | после W=20 прогонов — следующая стратегия по кругу + рост энергии |
| `noop` | мутация не изменила файл | не считается плато |

Порядок отката при shrink: `inject → append → expand → combo → field → delim → boundary → byte → multi`.

Девять стратегий: `byte`, `multi`, `boundary`, `append`, `expand`, `delim`, `field`,
`inject`, `combo`.

Журнал смен — `adapt.log`: номер прогона, `from → to`, причина,
`BB_run/BB_parent/BB_global`, энергия, веса стратегий.

## Что куда пишется

| Путь | Роль |
|---|---|
| `lab1/vulns/` | оригиналы `vuln2.exe`, `func.dll`, `config_2` — только чтение |
| `lab1/work/` | рабочие копии; мутант всегда имя `config_2`. В git нет |
| `lab1/crashes/` | `crash_*.bin` — упавший вход; `crash_*.txt` — исключение, регистры, стек, замены |
| `lab1/fuzzer/corpus/` | сиды, давшие новые BB |
| `adapt.log` | смены стратегий |
| `seq.log`, `cov.log` | журналы прогонов (отключаются `--no-log`) |
| `config.json` | локальные пути; копируется с `config.json.example`, в git нет |

Перед работой фаззер копирует exe/dll из `vulns/` в `work/` и в конце проверяет,
что оригинал `config_2` не изменился (SHA-256).

## Как устроен прогон

`auto --seq` и пункты 3–7 идут **под отладчиком** (`DEBUG_ONLY_THIS_PROCESS`,
32-битный контекст через `Wow64GetThreadContext`): при исключении сохраняются код,
регистры и дамп стека.

`auto --cov` сначала гоняет `drrun -t drcov`; каталог конфигурации DynamoRIO
подставляется свой (`work/dynamorio_config`), иначе при недоступном `%TEMP%`
регистрация клиента падает. Если `drrun` упал без лога покрытия, прогон помечается
как сбой инструментирования, а не как краш цели.

Крашем считается исключение `0xC000xxxx`. Штатный выход `exit(-1)` (несовпадение
номера варианта) крашем **не** считается. Логи `drcov*.log` после разбора удаляются.

## Файлы кода

| Файл | Роль |
|---|---|
| `fuzzer.py` | меню, CLI, проходы seq, цикл cov, сохранение краша и журналы |
| `mutations.py` | мутации и детерминированные проходы |
| `adapt.py` | планировщик стратегий (доп. задание) |
| `runner.py` | запуск с/без `drrun`, таймаут, каталог конфигурации DynamoRIO |
| `coverage.py` | разбор лога `drcov` |
| `debugger.py` | отладочный цикл, регистры, дамп стека |
| `config.py` | чтение `config.json` |

## Типичный порядок для отчёта

1. `auto --seq` — детерминированный поиск (журнал `seq.log`).
2. `auto --cov --max-runs 800` — покрытие и адаптация (`adapt.log`, `cov.log`, `corpus/`).
3. Если появился файл в `crashes/` — пункт 7 или x32dbg на `work\vuln2.exe` с этим
   конфигом (скопировать `.bin` в `work\config_2`).
