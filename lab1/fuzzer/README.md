# Фаззер lab1 (вариант 2)

Слепой мутационный фаззер файла `config_2` для `vuln2.exe`. Формат конфига в код не зашит: мутации портят байты как есть. Покрытие снимает DynamoRIO `drcov`. Доп. задание: если покрытие прогона падает или не растёт — фаззер сам меняет тип мутаций.

Python 3.12, только стандартная библиотека.

## Запуск

Из этой папки (`lab1/fuzzer/`):

```text
py -3.12 fuzzer.py                 меню
py -3.12 fuzzer.py auto --seq      авто: все смещения × граничные значения
py -3.12 fuzzer.py auto --cov      авто: очередь по покрытию + адаптация
py -3.12 fuzzer.py auto --cov --max-runs 500
py -3.12 fuzzer.py mutate append   одна мутация выбранного типа и запуск
py -3.12 fuzzer.py run             один запуск текущего lab1/work/config_2
```

Меню без аргументов:

| Пункт | Что делает |
|---|---|
| 1 | то же, что `auto --seq` |
| 2 | то же, что `auto --cov` |
| 3 / 3a | замена 1 байта / нескольких |
| 4 | допись в конец файла |
| 5 | вставка байт внутрь (файл длиннее) |
| 6 | мутация вокруг разделителей `,:=;` |
| 7 | запуск `work/config_2`; при падении — регистры и стек |
| 0 | выход |

Остановить авторежим: Ctrl+C. Краш не затирается.

## Что куда пишется

| Путь | Роль |
|---|---|
| `lab1/vulns/` | оригинал `vuln2.exe`, `func.dll`, `config_2` — **только чтение** |
| `lab1/work/` | рабочие копии; мутант всегда имя `config_2` (так ищет exe). В git нет |
| `lab1/crashes/` | `crash_YYYYMMDD_HHMMSS.bin` + `.txt` (код исключения, EAX…EIP, стек) |
| `adapt.log` | смены стратегии: номер прогона, from→to, причина, BB |
| `config.json` | локальные пути; копируется с `config.json.example`, в git нет |

Перед работой фаззер копирует exe/dll из `vulns/` в `work/` и в конце проверяет, что оригинал `config_2` не изменился.

## Как устроен прогон

1. Взять сид (байты конфига).
2. Применить мутацию.
3. Записать `lab1/work/config_2`.
4. Запустить `work/vuln2.exe` с cwd = `work/`.

`auto --seq` и пункты 3–7 идут **под отладчиком** (debug-loop, 32-bit контекст через `Wow64GetThreadContext`).

`auto --cov` сначала гоняет `drrun -t drcov`. Если процесс умер с NT-исключением (`0xCxxxxxxx`) — тот же файл ещё раз под отладчиком, чтобы снять регистры. DynamoRIO и наш отладчик одновременно не живут.

Логи `drcov*.log` после разбора удаляются.

## Авторежимы

**`--seq`.** Для каждого смещения исходного файла — набор граничных значений из ТЗ (`00`, `FF`, `FFFF`, `FFFFFF`, `FFFFFFFF`, половины и ±1). Подстановка на месте, файл не удлиняется. Стоп: настоящий краш или конец прохода. На файле 1123 байт это ~13 тысяч запусков (несколько минут).

**`--cov`.** Первый сид — оригинальный `config_2`. Новые базовые блоки считаются только в `vuln2.exe` и `func.dll`. Мутант с новыми BB попадает в очередь. Тип мутации выбирает планировщик (`adapt.py`):

- `gain` — появились новые BB: сид сохраняем, вес стратегии растёт;
- `shrink` — в этом прогоне блоков меньше, чем у родителя (часто ранний выход). После 3 подряд — смена. Откат: `append` → `expand` → `delim` → `boundary` → `byte` → `multi`;
- `plateau` — 20 прогонов без новых BB: другая стратегия и больше «энергии» (длиннее допись).

Стоп: краш, `--max-runs` (по умолчанию 2000), Ctrl+C.

Крашем **не** считается `exit(-1)` / `0xFFFFFFFF` (программа так выходит, если испорчен номер варианта). В лог краша попадают access violation, stack overflow и другие `0xC000xxxx`.

## Настройки `config.json`

```json
{
  "drrun": "C:\\Tools\\DynamoRIO\\bin32\\drrun.exe",
  "timeout_sec": 5,
  "max_runs": 2000,
  "plateau_runs": 20,
  "shrink_streak": 3
}
```

`timeout_sec` — лимит одного запуска; при зависании убивается дерево процессов (`drrun` + `vuln2.exe`).

## Файлы кода

| Файл | Роль |
|---|---|
| `fuzzer.py` | меню, CLI, циклы seq/cov, сохранение краша |

## Типичный порядок для отчёта

1. `auto --seq` — дождаться конца или краша.
2. `auto --cov` — дольше из‑за DynamoRIO; не удалять `adapt.log`.
3. Если появился файл в `crashes/` — пункт 7 или x32dbg на `work\vuln2.exe` с этим конфигом (скопировать `.bin` в `work\config_2`).
