# Лабораторная работа № 2 — вариант 3

Полезная нагрузка: **записать в файл `ports.txt` номера открытых (слушающих) TCP-портов**.

В репозитории две реализации, обе проверены на `vuln3.exe`:

| Вариант | Payload | Нулей | Размер `config_3` | Статус |
|---|---|---|---|---|
| **Ассемблер** (`payload/sc.asm`) — основной | **585 байт** | 0 | 3159 байт | работает, 5/5 прогонов |
| **C** (`payload/sc_pic.c`) — альтернатива | 695 байт | 0 | 3269 байт | работает, 3/3 прогонов |

Запуск сторонних программ и консольных команд не используется — только WinAPI.

**Переключение между реализациями:**

```
copy exploit\config_3_asm exploit\config_3     :: ассемблер (основной)
copy exploit\config_3_c   exploit\config_3     :: C-версия

> Процесс после записи файла завершается с кодом `0x80000003` (ассемблер)
> или `0xC0000096` (C). Это косметика: нагрузка сознательно не вызывает
> `ExitProcess`, чтобы не тянуть лишний код. На `ports.txt` не влияет.

## Как устроена цепочка

1. `vuln3.exe` читает `config_3` и копирует данные в буфер функции `vuln_func`
   (2504 байта на стеке).
2. В конфиге после 54-байтового заголовка идёт 2516 байт `0xFF`, затем адрес
   возврата `0x62501297` — инструкция `jmp esp` в `func.dll`.
3. `vuln_func` выполняет `ret`, попадает на `jmp esp` и передаёт управление
   нагрузке, лежащей следом в стеке.

Формат `config_3`:

| Смещение | Содержимое |
|---|---|
| 0…53 | заголовок варианта (54 байта) |
| +4 | `shell_len` — длина нагрузки |
| +8 | `dst_len` — размер буфера (2500) |
| +16, +20 | копии этих же значений |
| 54 | 2516 байт `0xFF` (до сохранённого EBP) |
| 2570 | адрес возврата `0x62501297` (`jmp esp`) |
| 2574 | сама нагрузка |

Размер файла = `54 + 2516 + 4 + len(payload)`.

## Ассемблерная версия (основная)

### Сборка

```
python payload\build_asm.py
```

Внутри — одна команда:

```
nasm -f bin -o payload_asm.bin sc.asm
```

Скрипт заодно проверяет два жёстких ограничения: отсутствие нулевых байтов
и длину меньше 740 байт.

### Что делает нагрузка

1. Находит `kernel32.dll` по списку загруженных модулей:
   `PEB → PEB_LDR_DATA → InLoadOrderModuleList` (ntdll → kernelbase → kernel32).
2. В таблице экспорта ищет `GetProcAddress` сравнением имени
   (`repe cmpsb`, длина 14).
3. Через него получает `CreateFileA`, `WriteFile`, `LoadLibraryA`,
   загружает `iphlpapi.dll` и берёт оттуда `GetTcpTable`.
4. Вызывает `GetTcpTable(pTcpTable, &size, FALSE)`;
   буфер 0x1000 байт лежит прямо в кадре на стеке.
5. Идёт по таблице: строки по 20 байт, состояние `+0` (`2` = LISTEN),
   порт `+8` в сетевом порядке — переставляет байты и переводит в десятичный
   текст подпрограммой `DEC`.
6. Одной операцией `WriteFile` пишет всё в `ports.txt`.

### Приёмы, которые дали 0 нулей и 585 байт

| Приём | Зачем |
|---|---|
| строки в стеке закодированы сдвигом `+41h` и декодируются на месте | в файле нет нулевых терминаторов |
| константы собираются `xor` / `mov reg8` / `shl` | `mov eax, imm32` даёт нули |
| все смещения локальных данных < `80h` | короткие `disp8`, меньше байт |
| адрес строк берётся из `esp` после `sub esp` | не нужна абсолютная адресация |
| `movzx eax, ax` при разборе порта | порт занимает 2 байта, `al` его обрезает |

## C-версия (альтернатива)

Задание разрешает C «с использованием приёмов разработки базонезависимого
кода», поэтому она тоже доведена до рабочего состояния.

### Сборка

```
python payload\build_payload.py
```

Скрипт делает всё сам:

```
cl /c /O1 /Os /GS- /Gs- sc_pic.c
link /NODEFAULTLIB /SUBSYSTEM:WINDOWS /ENTRY:shellcode sc.obj
```

Затем достаёт `.text` (648 байт), кодирует его потоковым шифром **xorshift32**
с подбором сида так, чтобы ни один байт не стал нулём, и приписывает впереди
**декодер на ассемблере** (47 байт), который расшифровывает код на месте
и передаёт ему управление.

### Приёмы базонезависимости в `sc_pic.c`

* нет глобальных и статических данных — всё на стеке;
* нет строковых литералов — строки собираются из иммедиатов (`mkstr`);
* нет обращений к таблице импорта — адреса функций ищутся в рантайме;
* вызовы только через указатели;
* нет CRT (`/NODEFAULTLIB`), нет проверки стека (`/GS-`, `/Gs-`);
* `#pragma code_seg(".text$a")` ставит шеллкод первым в `.text`.

Проверка позиционной независимости: при `/O1 /Os` в объектном файле нет
секций `.rdata` и `.bss`.

### Почему нужен декодер

Компилятор C выдаёт около 9 % нулевых байтов, а конфиг копируется строковой
функцией — первый `00` обрывает копирование. Проверено экспериментально:
payload с единственным нулём не исполняется. Поэтому C-код кодируется, а
ассемблерный — просто пишется так, чтобы нулей не было.

## Ограничения, найденные экспериментально

| Ограничение | Значение | Причина |
|---|---|---|
| Нулевые байты в нагрузке | запрещены | конфиг копируется строковой функцией |
| Длина нагрузки | ≤ ~740 байт | иначе срабатывает защита стека (`0xC0000409`) |
| Размер буфера TCP-таблицы | ≥ 0x600 байт | иначе `GetTcpTable` вернёт 122 при ~70 соединениях |
| `ExitProcess` в конце | не вызывается | не нужен, файл уже записан |

```
python tools\verify_config.py

Скрипт сам удаляет старый `ports.txt`, запускает `exploit\vuln3.exe`
и печатает результат. Эталонный список слушающих портов можно получить
