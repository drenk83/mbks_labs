# Лабораторная работа № 2 — вариант 3

Полезная нагрузка: **записать в файл `ports.txt` номера открытых (слушающих) TCP-портов**.

Нагрузка написана **на языке C** с использованием приёмов разработки базонезависимого
кода (position independent code) — это разрешено заданием наравне с ассемблером.
Запуск сторонних программ и консольных команд не используется: только вызовы WinAPI.

## Как устроена цепочка

1. `vuln3.exe` читает `config_3` и копирует оттуда данные в буфер функции
   `vuln_func` (буфер 2504 байта на стеке).
2. В конфиге после 54-байтового заголовка идёт 2516 байт `0xFF`, затем адрес
   возврата `0x62501297` — это инструкция `jmp esp` в `func.dll`.
3. `vuln_func` делает `ret`, попадает на `jmp esp` и передаёт управление на
   нашу нагрузку, лежащую следом в стеке.

Формат `config_3`:

| Смещение | Содержимое |
|---|---|
| 0…53 | заголовок варианта (54 байта) |
| +4 | `shell_len` — длина нагрузки |
| +8 | `dst_len` — размер буфера (2500) |
| +16, +20 | копии этих же значений |
| 54 | 2516 байт `0xFF` |
| 2570 | адрес возврата `0x62501297` (`jmp esp`) |
| 2574 | сама нагрузка |

## Как собрана нагрузка на C

### 1. Приёмы базонезависимости

В `sc_pic.c` сознательно нет ничего, что требует загрузчика Windows:

* **нет глобальных и статических данных** — все переменные локальные, на стеке;
* **нет строковых литералов** — строки собираются в стек из иммедиатов
  функцией `mkstr` (символ хранится со сдвигом `+0x41`, чтобы в машинном коде
  не появлялись нулевые байты);
* **нет обращений к таблице импорта** — адреса функций ищутся во время
  выполнения:
  `PEB → PEB_LDR_DATA → InLoadOrderModuleList → kernel32.dll → таблица экспорта`;
  имена сравниваются по хешу FNV-1a (базис 0);
* **вызовы только косвенные** — через указатели, полученные в рантайме;
* **нет CRT** — сборка без стандартной библиотеки и без `/GS`.

Проверка: при `/O1 /Os` в объектном файле **нет секций `.rdata` и `.bss`**,
то есть абсолютных ссылок на данные нет.

### 2. Компиляция и линковка

```bat
cl /c /O1 /Os /GS- /Gs- sc_pic.c
link /NODEFAULTLIB /SUBSYSTEM:WINDOWS /ENTRY:shellcode /OUT:sc.exe sc.obj
```

* `/O1 /Os` — минимум размера;
* `/GS-` — без проверки стека (иначе нужен `__security_cookie` из CRT);
* `/Gs-` — без пролога `__chkstk`;
* `/NODEFAULTLIB` — без CRT;
* `/ENTRY:shellcode` — точка входа сразу в нашу функцию;
* в исходнике `#pragma code_seg(".text$a")` ставит шеллкод первым в `.text`,
  а `".text$z"` уводит вспомогательные функции в конец — чтобы `jmp esp`
  попадал ровно в начало нагрузки.

### 3. Почему одной компиляции мало

Компилятор C выдаёт **около 9 % нулевых байтов** (обнуление локальных,
`mod=01,disp=0`, `mov …, 0`). А `config_3` копируется строковой функцией —
первый же `0x00` обрывает копирование, и нагрузка не исполняется
(проверено экспериментально).

Поэтому готовый код кодируется:

1. блок `.text` (648 байт) шифруется потоковым шифром **xorshift32**;
2. **сид подбирается перебором** так, чтобы ни один закодированный байт не
   стал нулём;
3. впереди ставится **декодер на ассемблере** (47 байт, тоже без нулей):
   он берёт свой адрес из `esp`, расшифровывает блок на месте и передаёт
   управление в его начало.

Итог: **695 байт, 0 нулевых байтов**, при лимите порядка 740 байт
(дальше срабатывает защита стека и программа падает с `0xC0000409`).

### 4. Полная пересборка

```bat
python payload\build_payload.py
```

Скрипт сам найдёт `cl.exe`/`link.exe` (переменные окружения `CL`, `LINK`),
соберёт `sc.exe`, вытащит `.text`, подберёт сид, соберёт декодер через NASM
и запишет `payload/payload_c.bin`.

### 5. Пересборка конфига

```bat
python tools\make_config.py payload\payload_c.bin exploit\config_3
```

### 6. Проверка

```bat
python tools\verify_config.py
```

## Что делает нагрузка

1. Находит базу `kernel32.dll` через PEB.
2. Находит в её таблице экспорта `GetProcAddress` (сравнение по хешу FNV-1a).
3. Через `GetProcAddress` получает `CreateFileA`, `WriteFile`, `LoadLibraryA`.
4. Загружает `iphlpapi.dll`, получает оттуда `GetTcpTable`.
5. Вызывает `GetTcpTable` (буфер — на стеке) и разбирает таблицу:
   строки по 20 байт, состояние `+0` (`2` = LISTEN), порт `+8`
   (сетевой порядок байт).
6. Номера портов переводит в десятичный текст и одной операцией `WriteFile`
   пишет в `ports.txt`.

---

## Ограничения, найденные экспериментально

| Ограничение | Значение | Причина |
|---|---|---|
| Нулевые байты в нагрузке | запрещены | конфиг копируется строковой функцией |
| Длина нагрузки | ≤ ~740 байт | иначе срабатывает защита стека (`/GS`) |
| `ExitProcess` в конце | не вызывается | не критично, файл уже записан |

## Альтернатива

Ассемблерная версия (581 байт, 0 нулей) доведена до создания файла, но пока
пишет в него неверные значения — не тот адрес таблицы. C-версия проверена и
работает стабильно, поэтому в итог взята она.
