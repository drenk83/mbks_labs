# Лабораторная работа № 2 — вариант 3

Полезная нагрузка на ассемблере: **записать в файл `ports.txt` номера открытых
(слушающих) TCP-портов**.

Запуск сторонних программ и консольных команд не используется — только WinAPI.

| Параметр | Значение |
|---|---|
| Payload | **585 байт** |
| Нулевых байтов | **0** |
| Размер `config_3` | 3159 байт |
| Проверено | 5 прогонов из 5, список портов совпадает с эталонным `GetTcpTable` |

## Как устроена цепочка

1. `vuln3.exe` читает `config_3` и копирует данные в буфер функции `vuln_func`
   (2504 байта на стеке).
2. В конфиге после 54-байтового заголовка идёт 2516 байт `0xFF` (до сохранённого
   EBP), затем адрес возврата `0x62501297` — инструкция `jmp esp` в `func.dll`.
3. `vuln_func` выполняет `ret`, попадает на `jmp esp` и передаёт управление
   нагрузке, лежащей следом в стеке.

Формат `config_3`:

| Смещение | Содержимое |
|---|---|
| 0…53 | заголовок варианта (54 байта) |
| +4 | `shell_len` — длина нагрузки |
| +8 | `dst_len` — размер буфера (2500) |
| +16, +20 | копии этих же значений |
| 54 | 2516 байт `0xFF` (до сохранённого EBP) |
| 2570 | адрес возврата `0x62501297` (`jmp esp`) |
| 2574 | сама нагрузка |

Размер файла = `54 + 2516 + 4 + len(payload)` = `54 + 2516 + 4 + 585 = 3159`.

## Что делает нагрузка

1. Находит `kernel32.dll` по списку загруженных модулей:
   `PEB → PEB_LDR_DATA → InLoadOrderModuleList` (ntdll → kernelbase → kernel32).
2. В таблице экспорта ищет `GetProcAddress` сравнением имени
   (`repe cmpsb`, длина 14).
3. Через него получает `CreateFileA`, `WriteFile`, `LoadLibraryA`,
   загружает `iphlpapi.dll` и берёт оттуда `GetTcpTable`.
4. Вызывает `GetTcpTable(pTcpTable, &size, FALSE)`;
   буфер 0x1000 байт лежит прямо в кадре на стеке.
5. Идёт по таблице: строки по 20 байт (`MIB_TCPROW`), состояние `+0`
   (`2` = LISTEN), порт `+8` в сетевом порядке — переставляет байты
   и переводит в десятичный текст подпрограммой `DEC`.
6. Одной операцией `WriteFile` пишет всё в `ports.txt`.

Ни `cmd.exe`, ни `taskkill`, ни другие процессы не запускаются — только
`LoadLibraryA` / `GetProcAddress` / `GetTcpTable` / `CreateFileA` / `WriteFile`.

## Сборка

```
python payload\build_asm.py
```

Внутри — одна команда:

```
tools\nasm\nasm.exe -f bin -o payload\payload_asm.bin payload\sc.asm
```

Скрипт заодно проверяет два жёстких ограничения: отсутствие нулевых байтов
и длину меньше 740 байт (иначе срабатывает защита стека).

Пересборка конфига:

```
python tools\make_config.py payload\payload_asm.bin exploit\config_3
```

## Приёмы, которые дали 0 нулей и 585 байт

| Приём | Зачем |
|---|---|
| строки в стеке закодированы сдвигом `+41h`, декодируются на месте | в файле нет нулевых терминаторов |
| константы собираются `xor` / `mov reg8` / `shl` | `mov eax, imm32` порождает нули |
| все смещения локальных данных < `80h` | короткие `disp8`, меньше байт |
| адрес строк берётся из `esp` после `sub esp` | не нужна абсолютная адресация, код позиционно-независим |
| `movzx eax, ax` при разборе порта | порт занимает 2 байта, `al` его обрезает |
| вызовы WinAPI без `add esp` после них | `stdcall` чистит стек сам |

---

## Ограничения, найденные экспериментально

| Ограничение | Значение | Причина |
|---|---|---|
| Нулевые байты в нагрузке | запрещены | конфиг копируется строковой функцией, первый `00` обрывает копирование |
| Длина нагрузки | ≤ ~740 байт | иначе срабатывает защита стека (`0xC0000409` / `0xC0000005`) |
| Размер буфера TCP-таблицы | ≥ 0x600 байт | иначе `GetTcpTable` вернёт 122 (при ~70 соединениях нужно 1412 байт) |
| `ExitProcess` в конце | не вызывается | не нужен, файл уже записан |

## Проверка

```
python tools\verify_config.py
```

Скрипт удаляет старый `ports.txt`, запускает `exploit\vuln3.exe` и печатает
содержимое файла. Эталонный список слушающих портов можно получить через
`GetTcpTable` — с ним файл совпадает.
