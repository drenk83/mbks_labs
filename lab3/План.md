## Решения, которые дальше не пересматриваем

Субъект — по-прежнему имя исполняемого файла, не учётная запись Windows. Так устроен текущий драйвер, и так же устроена проверка на рисунках старого отчёта.

Файл, которого нет в XML, не ограничивается. Иначе фильтр запретит системе читать собственные модули. Файл, который в XML есть, ведёт себя как DACL: нет строки для этого процесса — отказ. Единица разрешает чтение или запись, ноль запрещает.

Файл правил защищён отдельно и в список объектов политики не входит. Его открывает только `fsctl.exe` и сам драйвер в момент перечитывания. Запись в XML не может выдать это право другому процессу.

Правила перечитываются только по IOCTL, не на каждой операции. Иначе требование «обновление через IOCTL» не выполняется, а запись журнала зацикливает фильтр.

Нотификатор один: загрузка образа. Постановка и снятие только по IOCTL. Пока команда «снять» не пришла, каждый загруженный модуль дописывается в журнал. При выгрузке драйвера нотификатор снимается обязательно, иначе колбэк останется в выгруженном коде.

Журнал: `C:\DriverConfig\image.log`. Файл журнала в политике не защищается. Описатель открывается в обработчике IOCTL при включении и закрывается при выключении. В колбэке только дозапись уже открытого описателя, без нового `ZwCreateFile`.

Управляющее устройство: `\\.\FsFilterX`. Коды через `CTL_CODE(FILE_DEVICE_UNKNOWN, …, METHOD_BUFFERED, FILE_ANY_ACCESS)`:

- `0x800` — перечитать `C:\DriverConfig\policy.xml`;
- `0x801` — поставить нотификатор загрузки образов;
- `0x802` — снять его.

IOCTL принимает только процесс с именем `fsctl.exe`. Остальным устройства отвечают отказом.

Консольная программа правил — новая, `lab3\fsctl\fsctl.exe`. `filetool` не превращать в неё: у них разные роли.

## Формат XML

Кодировка UTF-8 без BOM, перевод строки CRLF. Имена тегов и атрибутов фиксированы, пространств имён, комментариев и подстановок `&...;` нет. Разбор в ядре — свой, по этой схеме, не библиотека XML.

```xml
<?xml version="1.0" encoding="utf-8"?>
<policy>
  <file path="C:\DriverConfig\data\note.txt">
    <subject name="filetool.exe" read="1" write="0"/>
    <subject name="notepad.exe" read="0" write="0"/>
  </file>
  <file path="C:\DriverConfig\data\report.txt">
    <subject name="filetool.exe" read="1" write="1"/>
  </file>
</policy>
```

Пределы, которые парсер обязан проверять: не больше 32 файлов, не больше 8 субъектов на файл, путь и имя процесса короче 256 символов. Лишнее не копировать в буфер. Ошибка разбора оставляет предыдущие правила и возвращает IOCTL ошибку. Пустой или отсутствующий файл при первой загрузке означает пустую политику: обычные файлы разрешены, `policy.xml` всё равно закрыт для всех, кроме `fsctl.exe`.

`fsctl set` хранит в XML ровно то, что пользователь задал, и после записи сам шлёт IOCTL перечитывания.

## Что менять в драйвере

Файл `FsFilterX\FsFilterX\FsFilterX.c`. Проект, INF, высота и подпись сборки x64 Debug не переезжают.

1. Убрать вызовы `ReloadDatabase` из предобработчиков create, read и write. Оставить загрузку в `DriverEntry` и в IOCTL.
2. Заменить `ParseBuffer` разбором XML выше. Путь конфигурации — `\DosDevices\C:\DriverConfig\policy.xml`.
3. Если путь есть в базе, а процесса в его списке нет, возвращать отказ. Сейчас в этом случае возвращается разрешение.
4. Жёсткая проверка `C:\DriverConfig\policy.xml` в create, read и write. Разрешать, только если идёт собственное чтение драйвера (`gLoadingConfig`) или имя процесса `fsctl.exe`.
5. В read и write в начале пропускать `IRP_PAGING_IO`, как уже сделано для create.
6. В `GetProcessImageName` проверять выделенный буфер, а не указатель на аргумент: при неудаче `ExAllocatePoolWithTag` сейчас в запрос уходит пустой адрес.
7. Управляющее устройство и символическая ссылка, обработка `IRP_MJ_CREATE`, `IRP_MJ_CLOSE`, `IRP_MJ_CLEANUP`, `IRP_MJ_DEVICE_CONTROL` только для него. Запросы тома по-прежнему идут в минифильтр. В `NullUnload` снять нотификатор, закрыть журнал, удалить ссылку и устройство, затем снять фильтр.
8. Нотификатор. В колбэке `PsSetLoadImageNotifyRoutine`: время, PID, имя процесса, полный путь модуля. Строка дописывается в уже открытый `image.log`. Повторная постановка и снятие незарегистрированного колбэка не должны ронять драйвер. Флаг не даёт писать журнал повторно, если запись сама вызвала загрузку образа.

Имя `fsctl.exe` для IOCTL и для исключения на `policy.xml` — одна и та же проверка.

## Программа fsctl

Каталог `lab3\fsctl`, консольное приложение x64, обычный пользовательский проект, не драйвер.

Команды:

```text
fsctl set <путь> <процесс.exe> <чтение 0|1> <запись 0|1>
fsctl show
fsctl reload
fsctl notify on
fsctl notify off
```

`set` меняет один субъект одного файла в XML, остальные строки сохраняет, затем шлёт IOCTL перечитывания. Повторный `set` для той же пары заменяет флаги, а не добавляет вторую строку. `show` печатает текущий XML. `reload` только шлёт IOCTL. `notify on` и `notify off` только ставят и снимают нотификатор.

Открытие устройства: `CreateFile("\\\\.\\FsFilterX")`, дальше `DeviceIoControl`. Если фильтра нет, программа пишет, что устройство не открылось, и не меняет XML в командах, которым нужен ответ драйвера. Для `set` файл на диске обновляется только после успешного IOCTL, чтобы на диске и в ядре не разошлись правила.

## Порядок работы

Сначала драйвер и `fsctl`, потом загрузка и проверка, в конце отчёт. Сборку драйвера подписывать тем же сертификатом, SHA256. Установщик INF по-прежнему не использовать: раздел `DefaultInstall` ограничен сборкой 25952, на машине сборка 28000. Загрузка — `fltmc load FsFilterX`.

1. Парсер XML и отказ для субъекта, которого нет в списке файла. Собрать, подписать, загрузить со старым поведением перехвата. На этом шаге IOCTL ещё нет, поэтому правила читаются один раз при старте из подготовленного `policy.xml`.
2. Защита `policy.xml` и управляющее устройство. `fsctl set` и `fsctl reload` начинают работать без перезагрузки.
3. Нотификатор и журнал.
4. Обновить `install-filter.ps1`: готовить `policy.xml`, не затирать старый `Config.txt`, грузить фильтр, прогонять проверки ниже и писать результат в журнал, который скрипт уже использует.
5. Отчёт заново по новому ТЗ.

Пока фильтр загружен, пересобранный sys нельзя скопировать поверх работающего. Сначала `fltmc unload FsFilterX`, затем копия в `System32\drivers`, затем снова `fltmc load`.
