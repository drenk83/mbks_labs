### Белый ящик: mfva

mfva — учебное Android-приложение для сканера Appknox. Автор Viren Nadkarni, XYSec Labs, 2017, лицензия GPLv3. Пакет `com.appknox.mfva`, язык Java. Это не продукт: README прямо говорит, что ошибки вставлены нарочно. Сборка `compileSdk 30`, `minSdk 25`, `targetSdk 30`, `versionName 1.0`. Зависимости — AppCompat, OkHttp 3.8.0 и Jedis 2.9.0. На эмулятор приложение не ставилось, разбор по исходникам.

Пользователь видит один экран `MainActivity` и шесть кнопок: запросы к API, WebView, запись в настройки, цитата в журнал, MD5 и DES. Из этого экрана открываются только `ApiRequestsActivity` и `WebViewActivity`. Сервисы, приёмники и провайдер с экрана не вызываются. Они лежат в манифесте, чтобы сканер увидел экспортированные компоненты.

Ниже находки по категориям MASVS v1.

**Архитектура.** Точка входа — `MainActivity`. Экспортированные компоненты к сценарию этого экрана не относятся. Модели угроз в репозитории нет: открытые компоненты и сеть без TLS оставлены как учебная поверхность.

**Хранение.** В манифесте `android:allowBackup="true"`. Резервная копия забирает данные приложения, в том числе файл настроек. Кнопка на главном экране пишет случайное системное свойство (`java.home`, `os.version` и соседние) в `SharedPreferences` с именем `pref`, без шифрования. Кнопка журнала пишет цитату в logcat с тегом `YOLO`. Сами по себе это не секреты. Тот же приём рядом с паролем уже был бы утечкой.

Рекомендация. Поставить `allowBackup="false"`, не писать свойства устройства в настройки и не писать в logcat из кнопок экрана.

**Криптография.** Кнопка шифрования берёт DES в режиме ECB. Ключ из восьми символов лежит в исходнике. Провайдера `BC` в `build.gradle` нет и нигде не регистрируется, поэтому вызов на устройстве попадает в `catch`. Параметры алгоритма от этого не становятся годными. Тот же DES запрашивается в `ExportedActivity`. Android Keystore не используется.

```java
SecretKey keyspec = new SecretKeySpec("Gangnam!".getBytes(), "DES");
Cipher c = Cipher.getInstance("DES/ECB/ZeroBytePadding", "BC");
```

Рисунок 1 – HTTP и пароли в ApiRequestsActivity

Рекомендация. Не хранить пароль в клиенте. Токен на экран не выводить.

**Сеть.** Все адреса в `ApiRequestsActivity` — `http://vapi.appknox.io`: корень, `/tokens`, `/user/1`, `/user`, `/uptime` и `/uptime/s`. Клиент `OkHttpClient` без pinning. Заголовок `X-Auth-Token` ставится на тот же HTTP. В манифесте нет `networkSecurityConfig` и нет `usesCleartextTraffic`. При `targetSdk 30` платформа с API 28 ясный текст по умолчанию режет, поэтому на современном устройстве запросы, скорее всего, не уйдут. Исходник требование не передавать учётные данные открытым каналом всё равно нарушает.

Рекомендация. Только HTTPS и явный запрет cleartext.

**Платформа.** `WebViewActivity` включает JavaScript и открывает `http://example.com`. Своего `WebViewClient` нет, моста `addJavascriptInterface` нет.

```java
webView.getSettings().setJavaScriptEnabled(true);
webView.loadUrl("http://example.com");
```

Экспортированные компоненты:

| Компонент | exported | Разрешение | Что снаружи |
|---|---|---|---|

Рисунок 5 – exported и необъявленное CustomPermission

Рекомендация. У `ExportedService` и `ExportedReceiver` поставить `exported="false"` или повесить объявленное разрешение. `onBind` должен возвращать `null`, а не бросать исключение.

**Качество кода.** `minifyEnabled` выключен, код не сжимается. `hash.toString()` показывает не хеш. Оба сервиса не реализуют `onBind`. В `ApiRequestsActivity` строка исключения показывается через `Snackbar` с фонового потока.

Рекомендация. Ошибку показывать с главного потока и без внутреннего текста исключения. Хеш печатать байтами.

**Устойчивость.** Проверок отладчика, root, подписи и целостности нет. Для MASVS L1 этот раздел не обязателен. В учебное приложение с нарочными ошибками такие проверки добавлять не нужно: они мешают разбирать те же ошибки.

## Вывод

В mfva прямые ошибки — DES/ECB с ключом `Gangnam!`, MD5, пароли `user1` / `pass1` и токен по HTTP, резервная копия, WebView с JavaScript на `http://example.com`, а также сервис и приёмник без разрешения. Необъявленное `CustomPermission` остальные компоненты как раз закрывает. Yandex Mail 8.81.2 открывает чужое письмо через `EmlActivity`. На эмуляторе письмо с маркером `LAB5-EML-MARKER` открылось, Frida записала `openInputStream` на этот файл. Нативные библиотеки к письму не подключаются. Сканер в том же процессе загрузил `libcamera360-arcadia.so`. FlowDroid дал 18 путей и оборвался по памяти, письма среди них нет. Trueseeing собрал 8068 срабатываний в 37 групп без уровня High. APKHunt ошибся в числе экспортированных компонентов.
